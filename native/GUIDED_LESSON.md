# 한 실험을 끝까지 읽기: 같은 출발·도착, 다른 중간 경로

이 수업은 새 제어 알고리즘이나 학습 실험이 아닙니다. 이미 검증한 **동일 예산 입력별 Encoder 학습 비교**의 고정 정책을 다시 실행해, reference·현재 상태·token·힘을 한 시간축에서 읽게 하는 공개 수업입니다.

## 학습 질문

출발할 때 로봇 상태와 과거 이력이 같고, 마지막 목적 상태까지 같아도 중간에 오른쪽으로 갔다 돌아오는 경로와 왼쪽으로 갔다 돌아오는 경로는 다를 수 있습니다. **현재와 도착점 정보만으로 어느 경로가 요청됐는지 구별할 수 있을까요?**

먼저 예측하고, 실제 기록을 비교한 다음 설명합니다. 예측 문항은 사용자가 생각해보는 장치이지 교육 효과가 검증됐다는 증거가 아닙니다. 문항을 건너뛰고 바로 관찰할 수도 있습니다.

## 두 화면의 역할

**실험 수업**은 Python/native에서 계산한 기록을 재생합니다. 재생·정지·시간 이동은 저장된 표본을 읽는 조작입니다. 모델이 브라우저에서 학습되거나 물리를 다시 계산하는 것이 아닙니다. 초기 상태 선택도
이미 실행한 정상/오차 조건의 기록을 고르는 것이며, 움직이는 로봇에 새 힘을 주는 기능이 아닙니다.

**구조 탐색**은 기존 JavaScript 교육용 정책과 MuJoCo WASM을 실시간으로 실행하는 별도 경로입니다. 두 화면을 전환할 때 이전 실행은 일시정지되고, 가중치와 물리 상태는 임의로 초기화하지
않습니다. 녹화값을 실시간 정책 출력으로 표시하지 않습니다.

상태 조회의 `activeSurface`는 `native-lesson`(기록 재생)과 `exploration`(구조 탐색)을 구분합니다. 활성 화면과 값의 출처를 함께 확인합니다.

## 기록을 고른 기준

`evidence/matched_cues/pairs.npz`의 test split에서 허용된 pair ID 순서의 **처음 세 쌍**을 사용합니다. 성능이 좋은 장면을 고른 것이 아닙니다. Encoder seed는
미리 선언된 첫 seed 52101, 입력 표현은 관절 상태형입니다. 각 쌍의 두 방향에 대해 `full_future`와 `endpoints_only` 정책, 정상·초기 상태 오차 조건을 재실행합니다. 총 24개
궤적이며 각각 28 control steps / 0.56초입니다.

두 정책은 같은 기존 SONIC Decoder를 유지하면서 각 정보 형식에 맞춰 별도로 학습한 Encoder입니다. 여기서 한 정책의 입력을 가려서 다른 정책이라고 부르지 않습니다. 이 세 사례의 수치를 전체 40개
궤적·세 Encoder 초기화의 평균으로 표시하지 않습니다. 전체 실험은 [MATCHED_CUES.md](MATCHED_CUES.md)와
[측정 요약](../evidence/matched_cues/summary.json)을 참고하세요.

## 신호의 시각을 맞추는 규칙

각 프레임의 `state`와 `referenceNow`는 **같은 시각 t**입니다. `errorX`는 그 둘의 카트 위치 차이입니다. `decision`에는 t에서 Encoder가 실제로 받은
reference 구간, 계산된 latent·token, 요청 힘과 물리 제한 후 적용 힘이 들어 있습니다. 이 힘은 **t부터 다음 0.02초 동안** 적용됐습니다.

Native `decision`의 preview 시각은 `0.00, 0.08, …, 0.56초`입니다. 브라우저 구조 탐색의 `0.08, …, 0.64초` 입력과 같다고 읽지 않습니다.

`endpointMaxError`는 두 방향 각각의 `abs(final - initial)`을 모든 상태 성분에서 비교한 최댓값입니다. A/B 종료 상태 사이 거리가 아닙니다. 성분은 카트 위치 [m], 카트
속도 [m/s], 막대 각도 [rad], 막대 각속도 [rad/s]로 각각 확인해야 하며, 이 혼합 단위 메타데이터 하나를 m 오차로 표시하면 안 됩니다.

마지막 t=0.56초 표본에는 상태만 있고 새 행동은 없습니다. `decision=null`을 힘 0이나 token 0으로 바꾸지 않습니다. 물리 step 사이를 화면에서 임의로 보간한 값을 측정값으로 내보내지
않습니다. 느린 재생 속도는 화면 관찰 속도일 뿐, 시뮬레이터의 제어 주기를 바꾼 것이 아닙니다.

`endpoints_only`의 `decision.referenceWindow`는 현재·끝점 정보로 구성한 **실제 모델 입력**입니다. 원래 원하는 중간 경로는 `referenceNow` 및 별도
`reference` 배열에 그대로 있습니다. 원하는 경로와 모델에 제공한 정보를 혼동하지 않습니다.

그래프는 시작 위치로부터의 카트 변위를 mm로 확대해 보여줄 수 있습니다. 화면상 크게 벌어지는 선을 물리적으로 큰 이동이라고 해석하지 않습니다. 로봇 도식을 쓰는 경우도 그 배율과 실제 단위를 구분합니다.

## 검증과 재현

`export_guided_lesson.py`는 원본 SONIC 모듈과 저장된 체크포인트를 불러와 실제 MuJoCo를 다시 실행합니다. optimizer update는 0회입니다. 각 궤적의 완료 여부와 추적
오차를 기존 평가 함수 및 저장된 실험값 양쪽과 비교합니다. 모델 가중치·FSQ 설정·출처 hash를 확인하고, 입력·출력·행동 적용의 시각을 기록합니다.

```bash
export SONIC_UPSTREAM=/path/to/pinned/GR00T-WholeBodyControl
export PYTHONDONTWRITEBYTECODE=1 PYTEST_DISABLE_PLUGIN_AUTOLOAD=1
export WANDB_MODE=disabled HF_HUB_OFFLINE=1
python native/export_guided_lesson.py --output /tmp/sonic-guided-traces.json
python -m pytest native/test_guided_lesson.py -q
```

기존 `native/training.lock` 환경을 사용합니다. 새 solver·서비스·학습 프레임워크는 필요하지 않습니다. 배포된 기록은
[traces.json](../evidence/guided_lesson/traces.json)에 있으며, UI는 이 파일만 읽습니다. 누락·손상된 데이터는 오류를 보여주며 모양만 비슷한 가짜 기록으로 대체하지
않습니다.

테스트는 저장된 힘을 새 MuJoCo 데이터에 적용해 모든 상태를 다시 만들고, native 모델의 기록과 비교합니다. 표본 시각·같은 목표·상태 오차·마지막 행동 누락·조건별 결과가 일치하는지 검사합니다. 이는
데이터와 화면의 일치 검사이며, 모든 로봇이나 센서 잡음에서의 안정성을 증명하지 않습니다.

## 해석에서 넘지 않을 경계

이 수업은 한 고정 Decoder와 한 표시용 Encoder seed, 작은 CartPole, 짧은 시간 구간의 사례입니다. 정상 조건의 미래 정보 이점이 상태 오차나 낯선 동작에서도 항상 유지되는 것은 아닙니다.
선택한 사례에서 오차 조건을 바꿔 실제 차이를 확인하고, 결과에 맞춰 설명합니다.

“둘 다 완주했다”와 “같은 궤적을 정확히 따라갔다”는 다릅니다. 반대로 특정 기록의 첫 힘을 잘 맞췄다는 것이 모든 가능한 제어 방법에 대한 최적성 증명도 아닙니다. 실무적으로 재사용할 것은 이
비교·시간·단위·재현 절차이며, CartPole의 가중치나 힘 제한을 다른 로봇의 보편 설정으로 복사하지 않습니다.
